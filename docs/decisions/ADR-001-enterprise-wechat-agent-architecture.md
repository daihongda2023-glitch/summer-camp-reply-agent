# ADR-001: 采用问答内核与企业微信适配层分离的架构

## Status

Accepted

## Date

2026-06-20

## Context

夏令营自动回复 agent 需要部署在企业微信群，面向学生回答报名、线上学习、实践作业、面试选拔、入营准备和线下集训中的高频问题。当前资料已经明确了产品边界：只回答官方资料确认的信息；个人状态、录取结果、安全医疗、投诉争议和技术作业答案必须转人工；未命中问题如果系统没有真实记录能力，不能承诺“已记录”。

企业微信的群机器人 webhook 通常适合向群里发送消息，但是否能接收群内学生提问、识别被 @、读取上下文并自动回复，需要在实现前通过官方文档和企业微信后台能力确认。如果把问答逻辑直接绑定到某一种接入方式，一旦接入方式不可用或权限不足，就会拖慢整个项目。

## Decision

采用“问答内核 + 渠道适配器”的分离架构。

问答内核负责：

- 意图识别。
- 知识检索。
- 回复策略。
- 人工升级判断。
- 资料来源和有效期检查。
- 冷却去重。
- 未命中记录。

渠道适配器负责：

- 接收企业微信消息、被 @ 消息或运营手动输入。
- 将外部消息转换成内部标准消息。
- 将回复、待确认结果或人工升级记录送回企业微信或运营流程。

第一版优先实现本地可验证问答内核和运营半自动模式。企业微信互动适配器等官方接收消息能力确认后再实现。

## Alternatives Considered

### 直接使用企业微信群机器人 webhook 做完整自动回复

- Pros: 看起来最快，适合主动提醒和推送。
- Cons: 可能只能出站发送消息，无法接收学生问题；如果能力假设错误，会导致核心方案返工。
- Rejected: 接入能力未确认前风险过高。

### 先做完整 RAG 系统再接企业微信

- Pros: 后续资料规模变大时更灵活。
- Cons: 当前资料量小，高风险在回复边界和资料可靠性，不在向量检索复杂度。
- Rejected: 第一版会过度工程化，且更难保证不胡答。

### 只做静态 FAQ 文档，不做 agent

- Pros: 最稳，几乎没有误答风险。
- Cons: 不能减少群内重复提问，也不能形成未命中沉淀和阶段式提醒。
- Rejected: 不能满足“减少重复提问、提升线下集训体验”的目标。

## Consequences

- 可以在企业微信接入能力未完全确认前，先验证核心问答质量。
- 后续可以从本地手动输入、运营半自动、群内自动回复逐步升级。
- 实现时需要维护清晰的内部消息格式和适配器接口。
- 自动回复上线前必须补官方接入文档确认和测试群验证。
