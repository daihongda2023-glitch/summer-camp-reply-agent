# 夏令营 Agent 知识库结构

## 设计原则

知识库按“学生所在阶段”组织，而不是按资料来源堆叠。学生提问时真正关心的是“我现在该做什么”，不是答案来自招募文章、群公告还是线下手册。

每条知识建议包含：阶段、问题、标准回答、资料来源、适用时间、是否可自动回复、是否需要人工兜底、最后更新时间。即使当前先用 Markdown 维护，也应保留这些元数据，避免后续无法判断答案是否过期、是否能自动发送。

## 阶段目录

| 阶段 | 主要问题 | 自动回复边界 |
| --- | --- | --- |
| 报名申请期 | 报名对象、专业要求、报名入口、费用、活动亮点 | 可自动回复官方明确内容；不判断个人是否一定能入选 |
| 线上学习期 | 课程入口、学习要求、通知渠道、学习节奏 | 可导航到资料；缺少课程细节时提示等待官方通知 |
| 实践作业期 | 作业内容、提交方式、截止时间、评分关注点 | 只回答规则和入口；不代做、不泄露答案 |
| 面试选拔期 | 面试通知、形式、准备建议、结果通知 | 只回答统一规则；不查询个人结果 |
| 入营准备期 | 报到时间、交通、住宿、携带物品、设备要求 | 可自动回复线下手册内容；特殊情况转人工 |
| 线下集训期 | 每日议程、场地、餐饮、分组、导师答疑、紧急联系人 | 可高频服务；涉及安全、医疗、冲突等立即转人工 |
| 结营后延展 | 证书、成果展示、开源仓库、实习/培养机会 | 回答官方已公布内容；机会推荐以正式通知为准 |

## 建议字段

```yaml
id: faq.registration.target_students
stage: 报名申请期
intent: registration.target_students
question_aliases:
  - 哪些学生可以报名？
  - 报名对象是谁？
  - 跨专业能报名吗？
question: 哪些学生可以报名？
answer: 面向全国高校在校学生，重点欢迎计算机、人工智能、软件工程、电子信息、自动化、数学、数据科学等相关专业学生报名。具备编程基础，并对 MXMACA 软件栈、AI Infra、大模型推理、算子优化、开源实践感兴趣的跨学科学生也欢迎参与。
source: 招募文章
source_date: 2026-06
valid_until: 2026-08-07
auto_reply: true
needs_human_fallback: false
human_fallback_reason:
last_updated: 2026-06-20
owner: 运营
```

字段约定：

- `id` 使用稳定英文命名，避免后续重命名影响日志和统计。
- `stage` 必须来自阶段目录，不新增近义阶段。
- `intent` 用于触发和冷却去重，同一意图可对应多个问法。
- `question_aliases` 记录学生可能的自然问法，不要求穷尽。
- `answer` 只写可直接发给学生的内容，不混入内部备注。
- `source` 和 `source_date` 必填；时间、地点、费用、名单、截止日期等高风险信息必须可追溯。
- `valid_until` 可为空；活动节点类信息建议填写，过期后默认不自动回复。
- `auto_reply` 为 `false` 时必须填写 `human_fallback_reason`。
- `owner` 用于资料维护，不应在群内回复中暴露。

## 资料优先级

1. 最新群公告、正式通知、线下手册。
2. 课程/作业/面试专项说明。
3. 招募文章。
4. 运营人工补充的 FAQ。

如果资料之间冲突，以更新时间最新、发布渠道更正式的资料为准，并保留冲突记录。冲突记录至少包含：冲突问题、旧资料、新资料、判定依据、处理人、处理时间和最终采用版本。
